# Память LLM: Рыбка Дори (без памяти) и Рыбка Немо (с памятью)

Домашнее задание VPg01. Два Telegram-бота на одной кодовой базе, SQLite как долгосрочная память, команды сброса.

## Структура

| Файл | Роль |
|---|---|
| `bot_dory.py` | Дори — **без** памяти: каждое сообщение уходит в модель отдельно |
| `bot_nemo.py` | Немо — **с** памятью; команды `/mytheses`, `/reset`, `/reset_history` |
| `assistant.py` | Логика ботов без привязки к Telegram (сборка системного промпта, сброс) |
| `db.py` | SQLite: таблицы `history` (реплики) и `theses` (тезисы) |
| `llm.py` | Вызов OpenAI со structured output (`theses` + `message`), офлайн-заглушка `LLM_MODE=fake` |
| `cli.py` | Консольный чат с ботами (проверка без Telegram) |
| `test_memory.py` | 9 тестов: сравнение, рестарт, изоляция пользователей, сброс |

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env     # вписать BOT_TOKEN_DORY, BOT_TOKEN_NEMO, OPENAI_API_KEY
python bot_dory.py       # в одном терминале
python bot_nemo.py       # в другом
# либо: docker compose up -d --build
```

Проверка без токенов и ключей: `python -m unittest -v test_memory` и `LLM_MODE=fake python cli.py nemo --debug`.

## 1. Сравнение моделей

Различие в коде — единственное: что попадает в промпт.

* **Dory**: `ask_plain(SYSTEM_PROMPT, text)` — модель видит только текущую реплику.
* **Nemo**: `ask_structured(build_system_prompt(user_id), text)` — в системный промпт добавляются тезисы из БД и последние 20 пар «вопрос–ответ».

Результаты тестов (прогон на офлайн-заглушке, см. раздел «Что проверено»):

| Запрос | Dory | Nemo |
|---|---|---|
| «Меня зовут Никита» → «Я забыл имя, напомни» | «Я не знаю вашего имени…» | «Тебя зовут Никита» |
| «2 + 2» → «А умножить на 3?» | «Уточните, что умножить?» | «4 × 3 = 12» |
| «Расскажи про Питер» → «Что там можно посетить?» | «О каком месте речь?» | отвечает про Санкт-Петербург |

**С кем проще работать.** Разработчику проще с Dory: ~10 строк, нет состояния, нет БД, не нужно думать про рост промпта, приватность и очистку. Пользователю проще с Nemo: можно писать «а там?», «умножь на 3», не повторяя контекст, и бот реагирует на **неполные команды**, которые Dory вынужден переспрашивать. Цена памяти: растёт размер промпта (токены, стоимость, задержка), появляются состояния, которые нужно хранить, показывать (`/mytheses`) и уметь стирать (`/reset`).

## 2. Долгосрочная память (SQLite)

* После каждого ответа Nemo пишет в `history` обе реплики, а в `theses` — тезисы, которые вернула модель (дубликаты отбрасываются).
* При каждом запросе `build_system_prompt` читает из БД тезисы (последние 50) и последние 40 реплик и добавляет в системный промпт блоки «Тезисы из базы данных…» и «Предыдущий диалог…».
* Память читается из файла, а не из переменной в RAM, поэтому **после перезапуска бота контекст не теряется**; при старте в лог пишется `Загружена память из БД: пользователей=…, реплик=…, тезисов=…`.
* Отличие от урока: одна таблица с колонкой `user_id` вместо таблицы на каждого пользователя — проще чистить и не нужно подставлять id в имя таблицы.
* В Docker БД вынесена на том `./data`, иначе файл SQLite пропадает вместе с контейнером (как предупреждали в уроке). Для продакшена — PostgreSQL.

## 3. Управление контекстом

* `/reset` — удаляет и реплики, и тезисы пользователя («забыть всё»). Память других пользователей не затрагивается.
* `/reset_history` — удаляет только краткосрочный контекст, тезисы остаются (чтобы можно было сравнить два слоя памяти).

### Эксперименты

| Сценарий | Наблюдение |
|---|---|
| Накопление истории | Пока диалог короткий, всё работает. Промпт растёт с каждым обменом, пока не упрётся в лимит 20 пар: более старые реплики перестают попадать в запрос (проверено тестом `test_history_limit`). С настоящей LLM это означает рост стоимости/задержки и риск, что модель «потеряет» старые детали. |
| `/reset_history` | Имя («Тебя зовут Никита») бот вспоминает по тезису из БД, а вот «А умножить на 3?» продолжает считать от старого результата, потому что тезис «Результат умножения: 12» остался. Вывод: тезисы переживают очистку диалога и могут тянуть за собой устаревший контекст. |
| `/reset` | Бот полностью «забывает»: «Я не знаю вашего имени», `/mytheses` → «В памяти пока нет тезисов». Поведение возвращается к Dory. |
| Рестарт процесса | Без сброса бот сразу продолжает с того места: в логе загружены реплики и тезисы, на «Как меня зовут?» отвечает верно. |

Практический вывод: сброс нужен при смене темы (старый контекст путает модель и тратит токены), для приватности и для отладки; полезно иметь два уровня сброса.

## Что проверено, а что нет

* **Проверено:** вся логика БД, сборка промпта, рестарт, изоляция пользователей, оба вида сброса — 9 тестов проходят, консольный сценарий прогнан.
* **Ограничение:** проверка шла на офлайн-заглушке (`LLM_MODE=fake`), которая видит только то, что попало в промпт, и поэтому честно показывает, дошла ли память до модели. Это **не** настоящая LLM: её ответы шаблонные. Реальные вызовы OpenAI и Telegram в этой среде не запускались (нет токенов и ключа). Код вызова повторяет схему из урока (`client.beta.chat.completions.parse` + `response_format`), но на живой модели его нужно прогнать, и скриншоты из Telegram для сдачи нужно снять самостоятельно.
